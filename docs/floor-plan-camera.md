# 平面图机位渲染

主工作台 → AI渲染 → 平面图机位渲染，入口 http://127.0.0.1:4192/?feature=floorPlanCamera 。

主工作台里的生成参数与 START 使用共享伸缩栏和窄屏配置抽屉。摆放相机、标注工具和室内效果留在右侧画布。单独打开机位页面时沿用本页参数栏。

2026-11-10：主工作台和 Beta 的机位生图复用共享目录提供 Banana Pro。A1 固定标注图和已归档成图词复用一次，1K / 16:9 请求交付 1376×768，OneAPI 回执为 ¥1.00，未计空间推理、未重试；2K 和 4K 未实测。见[单张试跑证据](../outputs/floor-plan-camera/banana-pro-1k-20261110/report.md)。

## 操作

1. 上传一张 PNG/JPEG/WebP 平面图，最大8MiB、单边4096px、16MP。
2. 点击房间内放置相机，按住拖动可同时指定朝向。拖蓝点移动机位。将白色圆柄沿箭头方向推远会收窄视野、拉近会扩大视野，绕蓝点拖可转向。起手方向明确时锁定变焦或转向。默认水平视野50°（约38.6 mm），两侧菱形手柄可调35–100°。拖浅蓝框的远边或短柄，沿镜头方向扩大或收小取景范围。工具条的「显示取景框」默认勾选。取消后，画布和送模图去掉浅蓝矩形，编辑用短柄移到虚线三角远边。画布工具条可精调朝向和开角或将相机居中，等效焦距随开角显示。方向键移动，Shift＋方向键旋转，加减键调整开角，Page Up / Page Down 调整取景远近。机位采用服务端默认平视高度，当前为1.5米。
3. 在「生成设置」选择模式。默认「空间推理」需要选择一个空间推理模型，「空间与风格」可留空。选择「提示词直出」后，在「生成模式」下方的「直出提示词」框填写非空提示词（最多 4000 字）。两个输入框各自保存草稿。两种模式都可选多个生图模型、共同画幅与分辨率，每个模型 1–4 张、每批最多 12 张。空间推理默认优先 Gemini 3.1 Pro，其次初次采用当前 Key 首个可用视觉 Agent，失权不静默换模。
4. 在「摆放相机」画布确认机位和视野。工具条可勾选「裁剪视野」（默认关闭），将两侧视角射线延伸至原图边界，用角域与原图交集的外接矩形裁剪。矩形内全部图纸保留，包括虚线角域两侧的内容，不做三角形外蒙白。点击「送模预览」检查实际输入图，返回摆放相机后可继续调整。同一批的所有图片共用一张处理后的机位标注图和同一份提示词。空间推理模式每批推理一次，结果可看镜头摘要和画面词。提示词直出逐字使用输入，结果可查看最终提示词。两种模式都按模型归组，逐张显示成图、失败及归档状态。
5. 选择成图并下载 PNG，批次文件名带模型和序号。切换工作台功能保留图和机位；整页刷新后仅按旧任务ID查询，原图需重新上传，不自动重提生成。

整页刷新加载 v35 界面脚本及 v22 样式，几何、遮挡和标注模块分别为 v12、v3 和 v14。画布点击后无焦点外框，下拉选项沿用共享黑底白字和橙勾。更换平面图需重新放置相机，上传失败保留旧图。任务进行中锁定输入，未知提交只 GET 原任务。推理空白或上游截断时结束进度并显示「取景说明不完整」，保留当前机位与模型设置，可手动重新生成。明确无法确认取景时提示调整机位。默认折叠的提示词正文使用纯文本显示。

## 视野裁剪与预览（2026-11-20）

主工作台工具条「裁剪视野」按服务能力 `cameraLimits.cropToView:true` 启用；选中后冻结 `camera.cropToView:true`。省略或为 `false` 时沿用整图，历史任务和 Beta 编辑入口保持原行为。摆放相机始终使用完整原图。

裁剪取朝向 ± 水平视野/2 的两条无限射线构成角域，与原图矩形求交，再计算交集的外接矩形。它不受 `guideDepth`、三角末端横线或取景框开关限制。仅按矩形裁边，矩形内原图全部保留，虚线角域两侧的墙体、家具及其它上下文不蒙白；另加白色边距使蓝点完整。方向、图纸比例保持。矩形内角域外内容只是空间上下文，实际入镜仍按蓝点、朝向、开角及首墙遮挡判断。裁边和白色边距不是墙体。机位在图片边界且朝外、无正面积交集时返回 400，要求调整机位，不回退整图。

`POST /api/floor-plan-camera/preview` 接收 `referenceImage`、`camera` 和可选 `promptVersion`，复用正式送模的合成及压缩，返回 `imageUrl/width/height/sha256` 和可选 `crop`。预览不读取模型权限或推理资产，不创建生成任务；只在点击页签时请求，机位变动后重新点击刷新。`promptVersion` 仅用于兼容旧版 C 标记。

空间推理和逐张生图使用同一份裁剪后字节。Agent 主机位和远端命中点换算为提交图归一化坐标，原图机位另存 `source_position`；直出正文逐字保留。回执 `actual.referenceImageCrop` 以 `mode:view-rays-bounds`、`preservesContext:true` 区分矩形裁剪，保存原图尺寸、交集多边形、裁边、边距及转换后的机位；多边形只决定矩形边界。归档实际送模附件与 SHA，原件另存。历史 `mode:view-rays` 图像及说明保留原合同，不重建旧结果。裁剪不代表模型已通过构图或画质验收，本轮仅本地合成、替身与界面验证。

## 生成合同

工作流 `2026-11-07.floor-plan-camera.9`，功能 `floorPlanCamera`，配置声明 `pipeline: camera-view-agent-to-image-reference` 和 `imageGeneration: { mode: image-to-image, referenceImageCount: 1, referenceImageRole: camera-annotated-plan }`。批次提交必须冻结 .9。兼容 .8 的单图请求及历史单图结果，更早工作流返回 409。

空间推理：单张带机位平面图 → 视觉 Agent 生成视野摘要和画面提示词 → 同一张机位平面图加成图词 → 每张独立图生图请求。

提示词直出：同一套标注算法生成单张带机位的平面图，与用户原文直接进入逐张图生图请求。只校验原文非空、长度及控制字符，保留空白和换行。任务执行不读取 Agent 资产、不调用空间推理，也不拼接平视开场、摄影段或其他固定词。主工作台和 Beta 都可切换生成模式。

编辑画布和服务端共用蓝色机位圆点、中轴箭头、视野虚线三角、可选的浅蓝取景参考外框及遮挡标注。机位参数 `showFrame:false` 会隐藏矩形，蓝点、箭头、三角及遮挡填色照常绘制。外框沿图纸横竖对齐，包住三角并为蓝点留边，线宽为虚线的 1.5 倍。上传时通过 `POST /api/floor-plan-camera/annotation` 取得正向原图尺寸和墙线数据，画布按机位实时计算可见区，任务按同一原图和冻结机位复用同一套墙线及标注算法。坐标以左上角为原点归一化，朝向0°向上、90°向右、顺时针，视野依据真实图片长宽比计算。OneAPI 生图模型复用 `/responses` 图生图，GPT Image 2.5 Sunburst 和 GPT Image 2.6 两款走既有后台编辑。

虚线三角的两侧表示水平开角，默认边点距离为图像短边 27%。拖框后，三角远边到机位的轴向距离以图像短边比例冻结为可选的 `camera.guideDepth`，范围 0.05–1.5。手动距离独立于开角，外框与三角按新距离同步伸缩。共享算法在最长边640px的图上识别连续墙线，将每条视线截在首个遮挡处，蓝色填色只画在三角内。外框和末端横线供构图参考。手动拉框时，空间推理会收到用户指定的取景参考距离。实际遮挡仍按开角和首墙判断。墙线不足、机位在墙上或射线缺少足够边界时，不绘制蓝色填色，显示方向及视野三角。门扇开合、窗台高度、细线和非轴向墙需对照图纸。

v7 起，两侧有连续的近距离命中、中央有稳定的较远命中时，服务端向 Agent 附上中间远景的画幅分界及五处平面远端命中点。墙线也可能包含窗轨或深色物体，需要按图纸核对语义。

新任务的主工作台、Beta 和送模图共用标注，叠加蓝点、中轴箭头、虚线三角、浅蓝取景参考外框及三角内的淡蓝遮挡估算。完整图纸保留画外原色，按水平开角和首墙确定实际取景。历史已冻结的标注及归档保留生成时的样式。

Agent输入以用户原文开头，随后提供相机位置、朝向、水平视野、全画幅等效焦距、高度、图像尺寸及`camera.visibility_mode`。v9 额外根据冻结朝向换算图纸上对应照片正前方、左侧及右侧的近似方向，供 Agent 避免左右翻转。独立系统词要求识别机位所在房间、朝向首先遇到的墙面或物体、左右与近中远景、开口可见性、遮挡及边缘裁切，并把材质、照明和摄影质感落实为最终画面。v6 的英文画面词直接描述可见景物，保留家具露出的面、斜向、画幅裁切和有依据的尺寸，省略相机参数、图纸解释和推理过程。基本结构或机位无法确定时返回`UNRESOLVABLE_VIEW`并停止，不回退直生图。

Agent 按原机位、水平开角和首墙遮挡确定取景。紧贴机位、碰到边线或被机位点覆盖的物件，需要先找到实际可见的表面。只有可见表面确实跨画幅边缘才描述露出的局部，整件在画外的物品排除。Agent 取景时保留空地和空墙，只描述图纸有明确依据、原机位可直视的物品与门窗。摄影质感只作用于已确认的表面与空间。

v10 让 Agent 直接写一份用于成图的自然语言取景说明，不要求 JSON、固定字段、中英对译或段落结构。最终取景正文用成片的左、右、正前方及近中远景。图纸方位供 Agent 内部换算，正文里的双重标注保留成片方位，例如「图右侧（画面左前方）」转换为「画面左前方」。未换算的图纸或罗盘方位会阻断生图。摘要可展示清理后的前 4000 字符。旧双语取景对象仍可转成可读摘要与正文。空白、无法确认基本取景或上游明确截断时停止生图，并保留已知请求 ID 和费用。v9 起 Agent 输出预算为 8192 token。

历史 v2–v8 继续校验 `view_summary` 与 `image_prompt`。v9 继续按 `frame` 的中英取景字段编译，可从围栏、说明外包或六项顶层字段恢复完整对象。不确定项只进摘要，损坏或缺失必需字段会阻止该旧版合同的生图。

v6 起，成图词以一句“从图中标记的机位，以人眼平视拍成真实室内摄影，只呈现可见部分”开头，紧接 Agent 的可见画面正文。v6–v10 把可选用户原文附在取景正文后。v10 起加入独立摄影段，使用 Canon EOS R1 的全画幅成像风格、f/8、ISO 100，以及按冻结水平视野换算的等效焦距，并指定平直建筑垂线、自然 HDR 包围曝光、锁定白平衡、明暗细节及真实材质。双侧近墙条件成立时附加该机位的遮挡说明。v9 起取消以 `Keep bare walls and empty floor areas empty` 开头的通用固定收尾，取景仍使用 Agent 的可见性规则。工作台与 Beta 归档的「最终 Prompt」与送模正文一致。v6–v8 保留图纸墙体、开口与去标记短句，v2–v5 沿用历史编译。

v11 要求 Agent 先写机位和拍摄目标，再核对成片方位、首墙、真实开口、家具关系及画面边缘的露出范围。门弧不作为门已打开的依据。用户补充的空间信息由 Agent 按图核实并换算成片方位，适用的材质、风格和光线融入可见场景。程序只向 Agent 传一次用户原文，成图词使用融合后的自然语言正文，原文仍独立保存在结果与归档。

结果保留 `compiledPrompt` 与 SHA，以及生成时相机和模型快照。空间推理另保留 `viewSummary`、`scenePrompt`（取景正文）和推理身份。历史裁切结果及飞书逐图归档可继续读取当时冻结的 `foregroundCrop` 距离。当前任务记录 `actual.visibilityMode`、`actual.fullFrameEquivalentFocalLengthMm`、`actual.generationMode: image-to-image`、`referenceImageCount: 1`、`referenceImageRole: camera-annotated-plan` 及 `referenceImageSha256`。空间推理模式的 `agentInputImageSha256` 与生图参考图摘要相等。直出只显示实际送模的提示词。可读摘要用于人工核对，不是几何正确性的证明。

## 模型与任务

推理模型复用共享视觉Agent目录和当前Key权限，排除仅文本模型。`agentModelKey`必选，在准备、执行及Agent返回后复核模型身份与权限；明确选中的模型失权时阻断，不替换。

主工作台的「生图模型」提供 **Qwen Image Edit 2511**（`qwenImageEdit2511`），默认使用楚雄 ComfyUI，节点和权重就绪时可选。已验证的档位为 **1K / 16:9 / 1280×720 原生 PNG**；多选模型时依旧使用共同档位。提示词直出使用原文，空间推理使用编译后的画面词，两种模式都提交同一张带机位标记的平面图。勾选「裁剪视野」时提交裁后的矩形图。每张独立随机种子，40 步、CFG 4、Euler / simple。归档沿用「Qwen Image Edit 2511」模型选项，并记录 ComfyUI 任务 ID 与实际工作流参数。

2026-11-22 本机 4192 空闲重载，实时目录及飞书准入可用，浏览器已选中 Qwen 并回读 1K / 16:9。2118 项回归通过，替身验证直出从提交到成品与归档回执的路径；工作台集成未提交新生图。此前同工作流实际样本见[四路对照](../outputs/floor-plan-camera/qwen2511-route-comparison-20261122/report.md)。

2026-11-12，主工作台和 Beta 的空间推理新增 **GPT 6.1 Sol**（`gpt61Sol` / `gpt-6.1-sol`）。当前 Key 开放时可选择，实际推理模型写入两张归档表的「Prompt融合」。v12 与 964×1078 机位标注图通过一次 OneAPI `/responses` 推理及取景正文校验。DeepSeek V4 Pro 的当前路由按文本模型处理，实测未识别仅存在于图内的校验码。 [阿里云百炼模型能力](https://help.aliyun.com/zh/model-studio/deepseek-v4-pro)

生图目录提供十一款OneAPI候选：Banana 2/2.1/Pro、GPT Image 2、GPT Image 2.5 Sunburst/Flare、GPT Image 2.6 Sunburst/Flare、Seedream 5.0 Lite/Pro及5.5；是否可用由当前Key权限决定。默认GPT Image 2.5 Sunburst、2K、16:9、medium。尺寸按模型显示1K/2K/4K与16:9/4:3/1:1；Lite仅2K/4K，Pro和5.5仅1K/2K；5.5使用独立官方尺寸。同一批使用所有所选模型共同支持的分辨率与画幅。用户更改模型后可采用共同档并提示变化，配置刷新保留原选择。

GPT2.6保留独立“生图思考强度：模型默认/低/中/高”，指图像模型的`complexity`，与前置空间推理模型及`quality`不同。默认省略参数，显式值由共享图生图适配器传到Responses图像生成工具的`complexity`；结果只记`requestedComplexity`，公司网关的实际执行尚未实图验证。[官方指南](https://developers.openai.com/api/docs/guides/image-generation)、[Responses参数](https://developers.openai.com/api/reference/resources/responses/methods/create)。

- `GET /api/floor-plan-camera/config`：工作流、`generationModes: ['agent', 'direct']`、推理和生图模型目录、Prompt 身份、相机限制及批次设置。顶层 `available` 仍反映空间推理准入。直出只需支持该模式、所选生图模型和归档连接可用。
- `POST /api/floor-plan-camera/jobs`：`jobId/action:'render'/workflowVersion/referenceImage/modelSelections:[{key,complexity?}]/imageCount/camera:{x,y,heading,fov,height,guideDepth?,showFrame?}/resolution/aspectRatio/userRequirements`。默认空间推理追加 `agentModelKey/promptVersion/promptSha256`。直出在 .9 下传 `generationMode:'direct'`，用户原文必填，省略三个推理配置字段。旧单图使用 `modelKey/complexity?`。旧请求携带 `foregroundCrop` 时返回 400。
- `GET /api/floor-plan-camera/jobs/:jobId`：只读恢复同一任务，不重新分析或生图。
- 每张成功图返回 `sync`。通过 `GET /api/sync-jobs/:generationId` 查归档状态，失败可用 `POST /api/sync-jobs/:generationId/retry` 续传原记录。

继续复用既有任务幂等、同ID不同输入冲突、连接切换阻断和更新忙碌守卫。Agent失败、空输出、无法理解机位或返回后配置漂移时零次生图；并发上限为 2，每张只调用一次图片模型。某张失败保留同批成功图和该张失败原因。空间推理批次在顶层记录 `receipts.agent`。直出结果与归档标记 `generationMode:'direct'`，无 Agent 资产、输入图或推理回执。各 `items` 按模型与组内序号记录结果或失败及已知生图回执。

## 批量跑图

从批量跑图的功能选择「平面图机位渲染」，载入或新建图片样本集，为每张图设置机位、朝向和开角，并可拖外框的远边或短柄调整取景远近。弹窗的「显示取景框」随样本机位保存。机位配置加载后即可编辑，生成仍校验所选模型权限。原图保存在飞书样本库，编辑中的机位按样本 ID 保存在当前浏览器。提交后精确机位随每个 Run 冻结到飞书跑图明细。Beta 样本列表使用最长边 360px 的缩略图。打开云端样本的机位弹窗时，底图与墙线从同一次标注请求读取，画布使用与墙线尺寸一致的正向图片。生成继续从样本原件制作送模标注图。

在「生成模式」选择「提示词直出」，填写一条整批共用的固定提示词。每个样本仍生成自己的机位标注图，每张生图请求都保留整批提示词原文。Beta 配置用 `betaGenerationModes` 声明支持，直出 Run 传 `floorPlanCameraGenerationMode:'direct'` 和原样的 `input.prompt`，省略空间推理的模型、版本和摘要。服务端校验同批模式和直出词一致。飞书配置快照保留模式和原文 SHA，实际生成参数保留送模图与生图回执，Agent 字段留空。只记录生图费用，冷恢复继续核验原文、双附件与逐图回执。

空间推理模式下，同一个样本机位在模型横评中共用一次空间推理、同一张实际机位标注图和同一份成图提示词。模型和张数展开成独立 Run。两种模式均可每个模型选 1–4 张，每个机位最多 12 张，尺寸和画幅取所选模型共同支持的档位。模型网关回执逐图保存，共享推理费用只归到同组的一条成功结果。

任务归档到 Beta 跑图明细。归档保留最终词、相机、模型、Prompt 版本、回执和实际送模图，下载校验送模图与结果图的 SHA 后展示成功。单图失败可按原批次手动重试，已有成图只续传归档。完整接口见 `GET /api/beta/floor-plan-camera/config`、`GET /api/beta/sample-sets/:setId/samples/:sampleId/camera-annotation` 和 Beta 通用 `/api/beta/jobs`。云样本标注响应包含 `imageDataUrl`、`width`、`height` 和 `walls`。
