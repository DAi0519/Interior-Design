# 全景图美化与光影转换

主工作台与 Beta跑图的“全景图美化”共用正式生成服务。选择 Flux2 Klein 时使用 `panorama-r5-4@2026-10-28.1`，不再调用普通单图 Flux 工作流；其他支持2:1的模型继续走各自 OneAPI。

日常入口为 `http://127.0.0.1:4192/?feature=panoramaEnhancement`。2026-10-29已确认Main/Beta待运行且4192无外部在途连接后重载，实际目录回读R5_4版本和 `generationFeatureCapabilities.panoramaEnhancement.multipleLightingSelections=true`。缺少多选能力的旧进程阻断多光影提交；逐卡版本/SHA过时返回409且不创建生成任务。4193保留为此前授权的独立预览。

## 操作

1. 上传一张真实尺寸为2:1的 PNG、JPEG 或 WebP 全景图，单张不超过8MB。
2. 选择 Flux2 Klein；R5_4输出保持原图宽高，内部固定20个1536×1536、90°视角，不使用普通Flux的1K/2K与4K/6K超分档位。
3. “光影选择”与精模共用小勾图卡、11px正常名称和12px单行入口，多选仅显示“N 种光影”，不堆叠名称列表或重复摘要。“清空”放在标题动作行，清空不删手写要求；再点卡片可取消，多选后面板保持展开。选中须ID/版本/SHA一致，失效选择保留错误和生成阻断。每种光影独立生成，结果卡片显示模板名并沿用双列画廊横向对比。单模型的“生成张数”是每种光影1–4张，多模型每个模型/光影组合1张；Beta再乘样本数。
4. 未选光影模板且未填要求时，使用独立飞书全景美化Prompt保留原光影。选择光影库模板，或填写“光影要求”，即可测试光影氛围转换。模板与手写要求可以组合，同一份要求分别应用到每种光影，细化或覆盖各自目标。清空选择保留手写要求；Main/Beta草稿隔离，旧单卡草稿自动迁移。
5. 使用结果的360°预览检查左右接缝、顶底连续性、结构和材质本色，并对比目标时段、主次光、曝光与白平衡。

光影卡片图片仅用于浏览器预览，执行时只读取卡片提示词。模型输入始终只有待处理的全景原图，不上传或传入第二张光影参考图，也不提供图文模式。

## 提示词与归档

保留原光影时仍从独立全景Prompt表读取正文。光影目标模式使用本地 `panorama-lighting-transform@v1` 保护合同、光影库已上架卡片原文及用户要求，不拼入旧全景Prompt的“保留原照明”限制，不复用精模基础词或双图迁移规则。

模板在入队前和执行前强制读取，核验记录ID、版本及SHA；更新或下架即409阻断。飞书记录保留实际最终Prompt、用户原文、全景光影模式/卡片身份、最终Prompt SHA、R5_4工作流版本/源文件SHA、实际输出尺寸及产物SHA。浏览器配置只包含卡片名称、版本、摘要和预览URL，不含库内正文。

## 工作流与执行边界

源图：`workflows/panorama-enhancement/R5_4_workflow.api.json`。执行工厂为 `src/panorama-workflow.mjs`，专用传输为 `src/panorama-client.mjs`；保留源图四步Euler、CFG1、手工sigma及Sphere Gather/Scatter状态共享，最终通过PerspectivePanoramaMerge融合。

执行前核验23类节点、模型和连线；复用共享ComfyUI单次提交、排队/执行状态、唯一产物名与输出SHA校验。执行窗口20分钟；主链路不自动重提GPU，Beta的R5_4也只执行一次Attempt，已有结果归档失败优先补归档。CFG1沿用源图，界面隐藏负向编辑，本轮测试变量为正向模板和用户要求。

2026-10-28已读取默认MaaS真实节点/模型目录、飞书十张v3光影卡片和Main/Beta归档Schema；全套1448项测试通过，并在4193实机核对模板选择/清除与自定义要求、原尺寸R5_4控件及旧4192禁用提示。节点可用和合同测试不代表光影幅度、材质保护或接缝画质已通过实图验收。

2026-10-29多选验收：1512项全测通过，含六卡×模型/每卡张数展开、单项身份和共享底图、跨卡冻结及限额防绕过、Beta实际批次构造。浏览器核验桌面三卡连续选择、16px要求分组和360px两列布局无溢出；没有提交新的收费生成，实图效果仍按前述边界验收。
