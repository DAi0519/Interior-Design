## 无窗场景边界

三条完整 Prompt 均包含 2026-11-02 用户确认的光源适配边界。纯词正文要求：

> 只有原图可确认的室外开口及可行入射路径才支持自然光主光和相应直射。普通室内门洞、挂画、镜面、柜门和亮墙不视为室外光入口；不得为解释光影假设隐藏窗户。缺少支持证据时保持围合封闭，不生成无来源的直射日斑、窗格影、树叶影或阳光束；保留目标冷暖、柔和度和明暗层次，用可确认的既有光源适配，必要时弱化无法成立的光向与投影。

画外光仅作克制柔和补光，不能制造硬边窗光/无来源强主光或代替应承担照明的现有灯具。人工/混合目标须按可识别既有灯具安排主辅，并落实发光部位与附近受光、反射、遮挡和衰减；隐藏发光部位保持遮挡，不暴露灯芯、不新增灯带。日光主导且路径成立可低人工贡献；按职责点亮，不自动全开。规则在同一次出图内执行，不增加Agent或图像阶段。

这段属于精模完整控制 Prompt，不应散落到每张卡片重复维护。卡片仍描述目标光向、软硬、主辅关系、色温与曝光；完整 Prompt 负责让这些目标服从原模型事实。修改和编译检查不能证明 Seedream 等模型的实际补窗问题已通过成图验收。

用户完整成像原文继续保留在各模式完整资产中：

> 自然平衡室内与室外的曝光关系，避免过曝发白。阴影区域应保留完整的材质细节，并呈现真实的接触阴影、柔和的明暗过渡和自然的空间纵深。室外景观应真实、克制、柔和。

外景与室外曝光要求不得授权新增建筑开口；保留有效外景，缺失环境的补全只能发生在真实既有室外开口之外，且适配尺度、透视、时段、天气、曝光与反射。具体执行以所选模式完整正文为准，不从历史外景快照补词。

## Prompt 发布规范

1. 在精模 Prompt 表按对应稳定编码新建下一整数版本，默认下架；填写完整正文、展示名和变更说明。三种模式都使用纯文本，不复用旧时段、天气或色调模块列。
2. 实质修改必须升版。先核对前后正文、预期拼接、来源表和 SHA，避免同版本编辑改变已冻结任务。
3. 以真实工作流和图像客户端/同步替身检查实际送模正文、图数、图序、版本/SHA与归档一致。替身检查不产生真实画质结论。
4. 完整资产上架后，旧版本只下架，保留正文、记录与历史来源。不得静默修改旧归档或把失败任务换成新版本重新收费出图。
5. 刷新工作台配置，并回读真实运行目录。仅数据更新可刷新读取；若读取或编译代码变化，须在生成与同步空闲后重载日常 4192，再检查实际目录和界面。

缺失、下架、重复版本、非法正文及版本/SHA漂移必须阻断，不能跨模式、跨表或从本地历史回退。旧纯词携带独立公共规则冻结身份时返回 409，提示刷新并重新提交；未运行草稿可清理废弃字段，已运行任务和结果按原身份保留。

## 读取边界

| 模块 | 职责 |
| --- | --- |
| `refined-model-prompt.mjs / loadRefinedLightingPromptAssets` | 从同一精模表读取三种完整资产，提供真实表来源及正文 SHA |
| `refined-lighting-library.mjs / loadRefinedLightingAssets` | 独立读取卡片、版本/SHA与原附件；不依赖精模 Prompt 可用性 |
| `refined-lighting-library.mjs / loadRefinedRenderAssets` | 为精模组合卡片与三模式完整 Prompt 的运行目录 |
| `refined-render-prompt.mjs` | 冻结所选完整 Prompt 的 code/version/正文 SHA/真实来源，执行前复核 |
| `refined-lighting.mjs` | 冻结卡片与实际图片；精模统一先放用户补充，再拼对应完整Prompt与适用卡片；双图各走专用正文 |

精模 Prompt 读取失败时应保留已读卡片及真实错误，只禁用对应精模方式；不能连带使白模、全景和光影转换的卡片失效。公开目录不返回正文或附件 token。

## 卡片字段与版本

| 字段 | 维护要求 |
| --- | --- |
| 名称／编码 | 面向用户的简短名称及稳定小写英文编码；不同装修或家具不自动构成新光影 |
| 类型／分类 | 新运行资产为“光影预设”；自然光、人工光、混合光、电影质感用于运营分类 |
| 光影提示词 | 逐张原图判断，统一“氛围主题与基调／光源安排及主次／色温与曝光”三段；不重复精模控制规则 |
| 氛围参考图 | 唯一上架执行原件；新增或替换均为精确 1936×1090 像素的 WebP，单张不超过 8MB |
| 候选参考图 | 收藏同类素材与旧代表图，不参与预览、执行或自动轮换 |
| 版本／上架状态 | 正整数；改正文或展示图均新建下一版本，旧记录和附件只下架保留 |
| 说明／排序／变更说明 | 简述光影目标、安排顺序并记录修改、来源和验收边界；不把素材差异写成效果承诺 |

每个稳定编码只保留一个当前版本上架。界面按编码选取最高上架版本只是兼容读取规则，不能替代旧版下架；底层仍会读取全部上架版本，相同编码与版本重复时阻断。卡片整体 SHA 包含正文与原附件身份。仅提示词不送卡片图，但仍核验卡片身份；双图除卡片身份外还核验实际下载的原件字节、尺寸与 SHA。页面使用同源轻量预览，不把缩略图当执行原件。

卡片发布或图片格式升级时，先新建默认下架的下一版本并核对正文、图片和版本。确认主工作台、Beta及评测没有引用旧版的排队或运行任务后，上架新版并下架被替代的旧版；旧记录、原件、候选图和已完成结果继续留档。历史任务若因旧版下架无法重试，应提示显式重选当前卡片，不静默换版或自动重新收费生成。最后按编码核对上架数量均为一，刷新配置并回读九卡身份；仅图片编码转换也遵守同一流程。

## 示例图统一规格

2026-11-04 用户确认：以后所有新增或替换的光影库示例图均沿用以下规格，作为素材制作与上架检查标准。

| 项目 | 固定规则 |
| --- | --- |
| 文件格式 | WebP，扩展名 `.webp`，MIME `image/webp` |
| 精确尺寸 | 宽 1936 × 高 1090 像素，横版；上传后的原件也须保持此尺寸 |
| 压缩参数 | `quality: 90`、`effort: 6`、`smartSubsample: true`，沿用现有 WebP 有损编码 |
| 单图大小 | 不超过 8MB；每个上架版本的“氛围参考图”仅一张 |
| 画面处理 | 保持原有光影调性与主体比例；需要适配构图时先处理画幅，再输出精确尺寸，不拉伸凑比例 |
| 上架核验 | 上传后下载原件，核对 WebP 格式、精确尺寸、字节数与 SHA，再检查每个编码仅一个版本上架 |

原始图片和候选素材继续留档；以上规则用于新上架的示例图。服务端目前仍兼容读取历史 PNG/JPEG/WebP，文档标准不代表新增了运行时格式或尺寸强校验。
