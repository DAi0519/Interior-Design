## 设计与光影边界

原模型是空间结构、门窗开口、机位、透视、构图、全部物体与材质身份、本色和纹理的真源。光影目标可重建光向、软硬、主辅关系、明暗、色温、曝光与白平衡，但不能靠改设计来满足目标。图2只提供照明与摄影氛围，不复制装修、家具、材料色盘、开口或外景。

三条完整 Prompt 均先在同一次出图内静默辨认可确认的真实室外开口、可行入射路径与既有灯具，再适配目标。普通室内门洞、镜面、挂画、柜门和亮墙不是室外光入口；不以假想隐藏窗解释光影。缺少支持证据时保持围合封闭，不造无来源的直射日斑、窗格影、叶影或阳光束；目标中不成立的方向和图案可以弱化，保留冷暖、柔和度与明暗层次。画外光只作克制柔和补光，不作无来源强主光，也不替代应承担照明的灯具。看不到窗不等于证明整间无窗，自动策略只依据输入可确认信息保守适配。详见[无窗场景边界](refined-lighting-library.md#无窗场景边界)。

人工光、混合光或缺少自然光入口的目标按现有灯具位置和出光方式分配主光、补光与重点照明；承担照明的灯具须点亮，并在邻近可达表面产生方向、光色、遮挡、衰减一致的受光和反射。隐藏在灯体/灯槽内的发光部位保持原遮挡，以合理出光证明点亮；不能只把灯泡涂白，也不把装饰线或高光变成新灯带。日光主导且路径成立时允许人工灯关闭或微弱贡献；灯具按目标参与，不自动全开，不以全局提亮代替点灯。原图灯体、物体和材质本色继续锁定。

卡片描述按“主题基调／光源安排及主次／色温与曝光”三段执行，不把家具材质本色当光色，K 值与曝光级差属于渲染目标而非测量。摄影参照不授权改变机位；HDR与暗部细节不代表把暗处全部提亮。参考迁移在同一次请求中读取图2的三方面照明信息，并适配图1的真实开口与几何；不增加分析调用。

用户完整曝光、接触阴影、过渡、纵深与外景段保留在完整资产中。不能从历史快照自动补词，也不能把无条件“外景更亮”解释成新增窗户的授权。上述是提示词约束，实际无窗保真与光影贴合仍需真实成图验收。

## 光影选择与上传

Main/Beta 共用卡片选择器，默认收起且不自动选卡。44px 缩略图入口使用正常字号，单选显示名称，多选只显示“N 种光影”；卡片名称正常字重，以右上角小勾表示选中，不追加“已选”或整卡高亮。宽栏三列，窄栏两列；多选保持展开，单选宿主选后收起，Escape 收起并归还焦点。没有精模清除按钮。

渲染方式在卡片面板外，可分别勾选三种方式，默认仅提示词；全不选时阻断。切换保留卡片身份，不混合多个氛围，也不改变默认模型。版本、上架状态、刷新和真实错误直接显示，正文留在服务端，不增加常驻说明小字或维护链接。

上传区常显，最多一张氛围图。选预设后可直接上传，只有文件读取成功才替换全部预设、退出方式对比并锁定卡片；取消或非法上传保留原选择。上传图存在时不能选模板，删除后回到未选并解锁，不自动恢复旧组。轻量草稿不保存图片正文，恢复上传模式须重传真实图片。

卡片或已运行冻结身份失效时必须明确阻断。未提交的旧纯词草稿可清理废弃公共规则字段，卡片仍按原身份校验；已经运行的任务、结果和历史版本不得被静默改写。

## 多光影横向对比（2026-10-29）

Main 按“光影×渲染方式×模型×每组合张数”展开，单模型每张光影的每种方式允许 1–4 张，多模型每组合一张。Beta 再乘样本数，逐项生成独立 Run ID 和标签。3 张卡、2 种方式、1 模型且每组合 1 张，共 6 项；每项仍只有一张卡片和一套方式身份，底图在共享请求中只传一份。

再次点击已选卡片取消，取消最后一张后回未选。结果标题标注光影与方式。草稿 `presets` 和 `executions` 仅用于 UI 聚合，正式请求逐项展开为单个 `presetId` 与 `execution`。服务端按模型、光影 ID 和方式分组限制张数，改变版本/SHA不能绕过限额；并发沿用既有两路。

运行目录必须声明 `multiplePresetSelections` 和 `multiplePresetExecutions` 才允许相应多选；旧进程不能静默少跑。卡片下架或身份变化须重选，不自动替换目标。2026-10-29 的 80 项定向回归及 Main/Beta 浏览器多选检查属于当时交互证据，未触发收费生成，不作为本轮管理整合或画质验收结果。

## 请求与冻结

纯词新请求只冻结完整 Prompt 与卡片身份，不携带独立公共规则身份：

```json
{
  "featureMode": "refinedModel",
  "promptCode": "refined-lighting-base",
  "promptVersion": 6,
  "refinedLighting": {
    "mode": "preset",
    "execution": "prompt-only",
    "presetId": "<已上架卡片记录ID>",
    "version": 5,
    "sha256": "<卡片整体SHA-256>"
  }
}
```

服务端入队时补齐并冻结 `refinedPromptSha256`。纯词携旧 `ruleVersion/ruleSha256` 的已冻结请求返回 409，要求刷新后重提，不静默换词执行。新请求显式 original、空来源、非法字段或混用旧非默认 `refinedRender`/设计参考图在模型调用前拒绝。

| 路径 | Prompt 身份 | 光影／图片身份 |
| --- | --- | --- |
| 仅提示词 | 同表完整纯词 code/version/正文 SHA/source | 卡片 ID/version/整体 SHA；无 rule、第二图或第二图 SHA |
| 参考图迁移 | 同表完整迁移 code/version/正文 SHA/source | 对应双图 Prompt 的 ruleVersion/SHA、卡片身份、卡片原件 SHA |
| 氛围词＋参考图 | 同表完整图序前置 code/version/正文 SHA/source | 对应双图 Prompt 的 ruleVersion/SHA、卡片身份、卡片原件 SHA |
| 上传参考图 | 同表完整迁移 code/version/正文 SHA/source | 对应 Prompt 的 ruleVersion/SHA与用户第二图 SHA；无卡片身份 |

三种 Prompt 的 `workflow.promptSource` 都指向真实精模表 `tblrj2xypwHnh97E`，不再指向光影卡片表。两种双图的兼容规则身份由同一完整 Prompt 派生，不能继续引用旧卡片表复合 SHA。`workflow.promptCode/promptVersion/promptSha256/promptSource` 与实际正文必须一致；最终 Prompt 另含卡片和用户补充，不与控制 Prompt 的正文 SHA 混用。

纯词 `digestScope="source-original"`、`imageRoles={source:1}`；双图 `digestScope="input-originals"`、`imageRoles={source:1,atmosphere:2}`。双图保留实际第二图文件名、MIME、尺寸、字节与 SHA；摘要范围是原件，不等于 OneAPI 内部可能压缩后的传输字节。图1归输入图，图2复用风格参考图附件列，不增加结果列。

入队、执行与 Beta 建档/归档阶段按实际资产复核；缺失、下架、同版本正文/附件漂移或回读不一致不得标记成功，不用本地或其他模式兜底。历史成功结果与仅同步失败的已有图片可继续恢复，不能为重新归档再次收费出图。
