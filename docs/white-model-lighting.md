# 白模渲染的光影选择

主工作台在设计风格之后提供可选光影，复用既有飞书光影库的卡片与预览。默认“自动”，沿用白模智能默认/平台风格原有的照明设计；选中一张卡片后只将其三段光影提示词交给现有 Agent 整合。卡片图片仅用于界面预览，不下载为生成参考图，不增加 Agent 调用或出图阶段。Beta 本次不新增控件。

## 输入与优先级

- `whiteModelLighting` 省略或为 `null` 表示自动；预设严格只接收 `{presetId, version, sha256}`，不接收客户端正文、卡片图片或多选。
- 白模仍是空间、开口、家具与物体位置、机位、透视和构图的唯一事实来源。
- 材质和配色由原风格任务决定；预设控制时段、天气、主次光源、光向、软硬、色温、白平衡与曝光。光色不能当作材料本色。
- 用户明确补充的光影要求优先于卡片；卡片照明优先于风格参考图、Style DNA 与默认摄影描述中冲突的照明。空间保护始终优先。
- Agent 将照明整合进原有 `visual_application.photography`，维持原 JSON Schema。服务端不修改 Agent System Prompt，也不事后覆盖 Agent 输出。

飞书两套白模 System Prompt 增加条件协议：有 `white_model_lighting_target` 才覆盖默认明亮/中性白平衡与风格冲突照明，无该段沿用原规则；原全文逐字保留在新版本中。选择预设时若指定了不含此协议的历史 Agent，执行前返回 409，提示使用最新版本或回到自动。历史 Agent 的自动模式继续可用。

## 准入、缓存与恢复

运行目录的 `generationFeatureCapabilities.whiteModel.promptLighting=true` 声明服务端支持。旧服务仍可执行自动模式；选择预设时阻断提交并提示刷新服务，避免参数被静默忽略。

入队前与执行前均通过 `white-model-lighting.mjs` 读取已上架卡片并核对 ID、版本和资产 SHA。失效或下架返回 409，不自动改选其他版本。自动不读取光影库，因此光影库不可用不阻断原白模自动任务。白模不依赖精模的纯词、迁移或图文规则是否上架。

卡片身份与编译光影词 SHA 进入 Agent 缓存指纹；切换卡片会重新整合，同一卡片可复用。自动保持原指纹。任务冻结选择，历史省略字段恢复为自动；失效历史选择明确阻断，允许用户重选或回到自动。

生成记录原有 JSON 工作流元数据增加 `whiteModelLighting`，记录自动/预设、`prompt-only`、卡片名称/编码/版本/资产 SHA 和编译词 SHA；实际最终 Prompt 沿用既有归档。浏览器只接收身份与预览，不接收卡片正文，不新增飞书字段或修改原卡片。
