# 工作台 Prompt 顺序

所有接收用户补充的功能统一遵循：**用户需求 → 功能固定规则 → 预设／模板补充**。验收看最终发送给模型的正文；界面顺序、配置记录或文档顺序不能代替实际请求。此规则调整业务正文的排列，不改变API的system/user角色，也不取消功能既有的结构、选区与typed动作约束。

| 功能 | 最终传入方式 |
| --- | --- |
| 白模、风格转换 | Agent的用户消息以`user_requirements`开头；校验Agent输出后，出图JSON的首字段`user_requirements`保存用户原文，其余设计字段保持Agent原值。 |
| 空房、旧房 | Agent的用户消息同样以`user_requirements`开头；接受任意字段/层级的非空JSON或纯文本。对象JSON首字段保存用户原文，纯文本/数组则以`user_requirements:`段落前置原文，再接完整Agent正文。 |
| 精模三模式及上传参考 | 用户原文 → 对应完整控制Prompt → 适用卡片词。 |
| 全景光影 | 用户光影原文 → 球面保护合同 → 可选卡片词。 |
| 光影转换 | 用户光影原文 → 独立双图迁移规则。 |
| 效果图美化新增光影模板 | 用户原文 → 美化保护合同 → 卡片词；Flux的`zhiganEnhance`随后追加，后续节点再次编译不能前插或重复。 |
| 打光、AI渲染台 | 用户原文 → 明确的整体原灯/标注控光方案 → 固定边界、适用模板与摄影规则。 |
| 二次编辑GPT | 用户原文 → 选区/图序/参考用途规则 → 输出要求；无补充的参考图模式仅使用固定模板。 |
| 二次编辑Flux/Qwen、局部消除、自由生图 | 沿用直接传用户原文的链路；必要的模型图像标记不作为业务模板前缀。 |

质感增强、效果图氛围转换、旧六档美化、超分、扩图和多角度等没有自由补充入口的固定流程保持既有合同，不为统一顺序而增加输入控件或拼接隐藏字段。选择的模型、几何和输出参数仍通过各自协议传递。

设计类先缓存经准入的Agent正文，再在每次出图时前置用户原文，避免缓存复用漏失原文；组装版本进入缓存身份，防止沿用旧输入顺序的缓存。空补充不新增字段或段落，原有设计字段不被覆盖。旧房任务标签由独立参数生成，不能通过替换整段文本改坏用户原文。

2026-11-05起，空房与旧房的智能默认、带参考图智能默认及平台风格均取消程序中的固定输出Schema：不要求`scene_preservation`或`visual_application.materials/colors/photography`，允许新增字段、嵌套对象和数组，纯文本也可直接使用；支持JSON/text/markdown代码围栏，先剥壳再检查正文，缺少结尾围栏不绕过空/损坏检查。空白回复、无非空文字叶子的JSON（包括`{}`、`[]`、`null`、纯数值/布尔）仍阻断；以`{`或JSON数组值起始符开头却无法解析的回复视为损坏JSON，不降级为纯文本出图，`[SCENE]`等普通段落标签可用。JSON字符串只解包一次，正文即使形似对象也不再改义。只为两场景增加`flexible-output-v1`缓存身份，白模和风格转换校验不变。飞书当前Agent正文仍可能要求既有JSON，该写作要求与程序准入分开维护，本轮没有修改正文资产或版本。

用户补充仍限制8000字符并在Agent前校验；含原文和Agent设计内容的服务端合成正文使用独立32000字符应用上限，不截断原文或设计字段。空房/旧房没有补充时的Agent正文也统一用此上限，避免自由输出仍被原8000字符入口拦截。该额度只由内部构造参数开启，请求正文夹带同名字段无效；自由生图仍按原8000字符限制。此为本地准入额度，不代表对上游模型容量的承诺。

最终Prompt、原始用户要求和既有版本/SHA分别归档；实际请求与`finalPrompt`须一致。Main/Beta共用对应服务，不在页面重新追加第二份要求，历史归档保持原文。

离线回归覆盖设计类十一模式×OneAPI/Flux、缓存复用、空补充、多段原文、旧房标签、Agent同名字段、打光typed动作、二次编辑各定位与参考用途、Flux触发词幂等、实际节点及归档同文；空房/旧房另覆盖自由正文、围栏/段落标签/JSON字符串、无效输出和32000字符边界。本轮不提交收费生成、不改飞书Prompt资产；源码测试、4192空闲重载与真实画质分别验收，运行状态见[本机入口记录](local-entry.md)。
