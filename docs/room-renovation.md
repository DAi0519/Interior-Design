# 旧房改造

在生图工作台的「AI设计 → 旧房改造」上传一张旧房照片，选择房间类型、家具、设计风格及出图模型，点击 START。

2026-10-22 起，旧房与空房复用同一条生成流程和房型/家具/风格输入，但提示词独立维护：原图进入旧房专属 Agent，再由所选模型出图。旧房不读取空房 Agent 正文或版本，空房原有提示词保持不变。

每个方案只调用一次出图并归档一次，不再预先清空、生成清空图或拆分两阶段。提示词缓存、再次渲染、重新生成提示词、单模型多张和多模型批次均沿用空房已有逻辑；失败不会自动重复出图。

结果区使用共享结果画廊、原图/结果图滑动对比、下载及飞书同步状态。浏览器仍以 `roomRenovation` 独立保存任务引用，避免与空房入口互相覆盖；刷新可恢复服务进程内的任务，服务重启后的记录由飞书追溯。

提交现有 `/api/generation-jobs` 时沿用 `featureMode: "emptyRoom"`，旧房额外携带 `designScenario: "room-renovation"`，区分独立旧房 Agent 与 Flux 默认负向，不触发额外流程；不发送历史 `roomRenovation: true` 包装标记。与空房相同，执行前校验同步 Schema、完整空房参数及模型/Agent 准入，原图同时作为 Agent 和最终出图的主图。

生成记录继续归档在现有空房设计功能下，只产生一条普通设计记录；生成参数保存 `designScenario`、实际 `agentCode` 与 `agentVersion`，原始 Prompt 保持用户原文，最终 Prompt 与实际送模正文一致。不新增飞书功能单选或 Beta/Benchmark 枚举，页面不接收完整 Prompt。

旧房当前v4沿用v2的全面大改边界：只保留真实围合墙体与隔墙（含非承重隔墙）、柱梁、楼板层高、真实门窗洞口的位置/尺寸和原机位画幅。墙地顶饰面、非结构吊顶造型、护墙/背景墙、装饰拱/假柱、门窗框扇装饰、柜体、固定装饰、灯具、家电及全部家具软装都可重新设计；固定、嵌入或定制不等于结构。新方案按房型、明确家具需求、补充要求及目标风格统筹重做，不能退化为同布局换色或换材质。原装修轮廓、分缝、材质、配色、物件及摆放不作为保留依据；去除旧物后，可在同一画幅内露出更多有结构依据的墙地顶表面，不锁定旧遮挡范围。独立风格参考图仍只提供风格，不能迁移结构或布局。

## 独立提示词维护

唯一正文真源为飞书 [旧房改造 Prompt](https://lq9n5lvfn2i.feishu.cn/base/SALobKnnra17iSsGT2ccC52PnHd?table=tbl9aFZzK7AwF8qk&view=vewptTZ0Rh)，与「空房设计prompt」分表：

- 智能默认（含可选风格参考图）：`room-renovation-smart-default`，当前独立 v4；请求字段 `roomRenovationSmartDefaultVersion`。
- 平台风格融合：`room-renovation-fusion`，当前独立 v4；请求字段 `roomRenovationPromptAgentVersion`。

v1 从空房两条 v34 复制为独立记录，再仅在旧房副本写入“原图只参考结构、家具软装及原装修不作依据”的规则。发布前后逐条回读，原空房表31条记录的已投影字段完全一致；新表两条正文均按字符数与SHA-256回读匹配。

2026-10-23 仅更新独立旧房表：两路v2明确全面大改，把真实结构与装饰层分开；同步更新Task、Priority、Full Renovation Boundary、Rules、scene_preservation合同、材料/质量要求及Output Schema。删除旧吊顶/装饰轮廓和旧物遮挡范围的保留限制；v1保留历史并下架。空房表不改。

同日两路独立v3曾在飞书上架，继承v2的大改边界，强化整体设计与有主次的丰富度；v1/v2均保留为下架历史。v3同步更新Role、Task、Design Authorship、设计规则、材料/色彩/摄影字段合同和Output Schema的最终质量段，现有JSON字段不变。

以后在此独立表编辑 `System Prompt`；需要保留历史时复制记录、递增版本，完成后设为“上架”。工作台点击刷新配置读取新版本，智能默认使用当前已上架版本，平台融合可选择指定版本。旧房版本记忆与空房分开；未上架或表不可用时只阻断旧房，禁止回退到空房提示词。全下架不会令空房/白模连接失效。

程序直接发送表中的完整 `System Prompt`，Agent 返回的 JSON 仅校验并格式化后原样进入最终出图；不再追加代码内固定提示词，不覆盖 `scene_preservation`。提示词缓存按独立Agent编码、实际版本、完整正文及输入指纹隔离，修改旧房正文可独立生效。可用 `LARK_ROOM_RENOVATION_PROMPT_BASE_TOKEN` / `LARK_ROOM_RENOVATION_PROMPT_TABLE_ID` 指向同结构的独立表。

v3发布阶段完成两路发布、独立表正文及 `getPublishedPromptAgent` 实际读取正文的SHA-256匹配，原空房表31条记录全字段读回一致。调用 `POST /api/config/refresh` 后，`GET /api/styles` 回读旧房智能默认/融合均为v3、空房两路仍为v34；浏览器刷新已看到旧房风格融合Agent v3，并恢复原智能默认模式。该发布阶段未调用付费模型或执行真实生成；随后2026-10-23已完成以下三张真实样本，发布回读与成图质量分开验收。

## v4最终提示词先清旧、再完整设计

两路独立旧房Agent当前均上架v4；v1–v3保留下架历史。最终JSON层级和字段名不变，第一叶字符串`scene_preservation`强制逐字以以下两句开头，不能先写Preserve或其他前言：

> Clear out all existing furniture, soft furnishings, cabinets, appliances, lighting fixtures, surface finishes and non-structural decoration from image 1; discard their original arrangement, decorative forms, materials and colors. In this same image, create a completely new, fully finished and fully furnished interior using the resolved furniture placements, layout, architectural finishes, joinery, lighting and styling specified below, never an empty room, demolition view or intermediate stage.

随后才简洁列出该图有证据支持的真实结构、洞口与原机位。清空指令只作用于旧装修与物件，不授权拆改真实围合墙/隔墙、柱梁、楼板或真实门窗洞口。`materials`仍为四个实质段落，但首段直接以Place/Install/Build等执行句给出新家具的所在墙段、朝向、尺寸关系和通行；后续依次落实新墙地材质与构图、新非结构顶面/门窗装饰/木作及节点、新家具造型/织物/灯具/艺术品和成组陈设。不得只写may be redesigned、概念介绍或旧物换色。有限空间中的合理床位可重复，但必须独立解题并重做家具及整屋设计，不能为强挪位置破坏结构、通行或原视角。

旧柜轮廓、装饰拱、镜/框玻璃、包边、假凹位不自动视为受保护结构；单图无法确认的底层几何不能臆断。旧植物、书堆、矮凳等不是默认保留需求。Task、Priority、边界、设计规则、字段合同、Schema、quality及静默自检一起更新，程序不拼前缀、不改写Agent输出，不重新引入清空图或第二次生图。

## 旧房 Flux 专属默认负向

旧房默认负向由服务端 `AI_TEXTURE_ROOM_RENOVATION_NEGATIVE_PROMPT` 独立维护，只在已准入的 `featureMode=emptyRoom` / `designScenario=room-renovation` 请求中选择。它允许重新设计原家具、材质、饰面、配色与全部装饰，不再包含保留原材质/颜色、禁止哑光改亮光或笼统禁止新增物件的约束；只排除真实围合墙/隔墙、柱梁、楼板层高、真实门窗洞口的位置/尺寸，以及机位、焦距、透视、画幅的变化，并排除几何畸变、悬浮/穿插/尺度错误、塑料感、不合理光照和噪点等质量缺陷。结构与原视角仍须保留，负向文本本身不构成几何保真保证。

空房、白模及其他普通 Flux 功能继续使用原 `AI_TEXTURE_DEFAULT_NEGATIVE_PROMPT`，原文全文不变；独立旧房 v3 Agent 正文和版本也未因此次负向拆分而更改。负向留空使用所属场景的默认，非空自定义内容仍整段覆盖、不隐式拼接，去除首尾空白后的上限保持 8000 字符，且不传给同批 OneAPI 模型。实际模式与完整生效文本继续写入生成参数 `workflow.negativePromptMode` / `workflow.negativePrompt`。

前端仅在选择 Flux 时显示输入框和说明。旧房与普通功能各保留一份独立内存草稿，切换功能不互相继承自定义内容，不新增持久化；普通功能仍共用原有草稿范围。旧房空值说明允许改材质、配色、家具与装饰，并要求保留真实结构和原视角；非空说明明确本次整段覆盖旧房专属默认。浏览器只显示状态说明，不接收服务端默认正文。

本功能评测原件已按SHA去重，关键记录与完整Prompt保存在[统一最终目录](../outputs/room-renovation/final/report.md)；旧文件名仅作合并证据的历史来源标识。
