# 旧房改造

在生图工作台的「AI设计 → 旧房改造」上传一张旧房照片，选择房间类型、新方案家具、设计风格及出图模型，点击 START。

1. 清空：移除家具、家电、杂物及活动装饰，保留墙体、门窗位置、墙地顶、固定柜体和原机位。
2. 设计：读取实际清空产物，复用当前空房设计 Agent、家具需求、智能默认/平台风格/风格参考图及所选出图模型，完成装修和家具方案。

每个方案独立执行两次出图；选择多模型或多张时，每一项各自清空和设计。清空不接收用户设计要求和目标风格，避免第一步提前装修。清空与设计均不自动重试；第二步失败仍保留已清空图片，重新点击 START 会重新执行两步。

结果区默认显示设计图，可切换原图、清空图、设计图，下载按钮跟随当前图片。刷新浏览器依靠原有后台 jobId 恢复三图，服务进程重启后任务会过期，须通过飞书记录追溯。

浏览器以 `roomRenovation` 保存独立任务；提交现有 `/api/generation-jobs` 时使用 `featureMode: "emptyRoom"`、`sharedInput.roomRenovation: true`，其他房型、家具和空房双 Agent 字段保持原合同。两阶段生成前先通过现有同步 Schema 和完整空房参数准入。

两个阶段继续归档在现有空房设计功能下，标题区分「旧房改造 · 清空 / 设计」，生成参数以 `pipelineId`、阶段、清空记录 generationId、实际 Prompt 版本及原图/中间图 SHA-256 关联，不新增飞书功能单选或 Beta/Benchmark 枚举。页面只接收图片、阶段、身份及同步回执，不接收完整 Prompt。

固定指令不构成几何或清空质量保证。验收需要同时查看三图，检查物品是否清理干净、门窗洞口和透视是否保持，以及最终设计是否符合房型、家具和风格要求；不能只以请求成功判定功能质量。

## 柜体体积约束（空房 Agent v34）

旧房改造与普通空房设计共同使用已上架的 v34 智能默认/风格融合 Agent。新柜体应具有真实收纳深度和可用体积；无原始可见凹位时，贴墙落地柜须在原墙面前方向室内占地，不能挖墙、移墙或凭空造壁龛藏柜深。吊柜、镜柜按实际安装关系悬挂，独立柜、岛台、通顶及定制柜继续允许；侧板、端板、接地或安装节点以原机位可见性为准，不改视角或编造精确尺寸。系统合同要求 scene_preservation 的最终出图词保留原墙面并禁止新造凹位、凿墙或移墙，materials 描述无凹位贴墙柜的柜背、前凸柜门面及之间可用体积。工作台刷新飞书配置后读取 v34，v32/v33 历史版本保留并下架。

文字约束已上架不等于每张成图都几何正确；同图回测应分别检查最终 Prompt 是否描述柜体体积，以及实际图片是否保持原墙面、柜深、开口和通行。

2026-10-21 使用同一清空图、Flux2 Klein 默认 9B FP8 / 7 steps、Gemini 3.1 Pro 分别真实回测 v33/v34 的智能默认与现代简约融合，四项均生成成功并归档；每版每模式仅一张，随机种子不同，不构成稳定提升或因果证明。v34 融合图的柜端侧板、柜门转角和底部接地已形成明确体积；智能默认仍主要露出正面，柜深只部分可辨。两图窗洞或墙垛比例均有漂移，原结构保真未通过。实际最终 Prompt 均写出向室内凸出，但仍未完整传达禁止凿墙/造凹位及柜背—门面的全部关系。上架和运行合同已验证，整体几何质量不能标记为已解决。证据索引见 `.impeccable/review/cabinet-geometry/validation.json`，完整 Prompt 与产物保留在忽略目录 `outputs/cabinet-geometry/2026-10-21/`。
