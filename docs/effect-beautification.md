# 效果图美化氛围与光影模板

主工作台与 Beta跑图使用同一个十五项模板网格，卡片尺寸、底色及勾选一致：原六档为无图卡，九卡带真实预览，不插占位图片。两处均支持原六档与九卡混合多选、再次点击取消、全选/清空；勾选时保持展开，多选摘要只显示“N 种光影”，空选阻断。主工作台按模板×模型展开独立任务；单模型每模板1–4张，多模型每模板每模型一张，结果标签含模型与模板。Beta再乘样本数，按参数和身份恢复草稿。每个独立请求只使用一种氛围：原六档保留各自工作流，仅新增卡片固定低自然，不把多个模板词合并到同一张图。

主工作台多选须由实际运行目录声明 `generationFeatureCapabilities.effectBeautification.multipleLightingSelections=true`，旧进程禁用多选提交并提示重启。后端按模型与原六档配置或卡片ID逐组合计数，改变卡片版本/SHA不能绕过限额；混选只要含原六档，就必须有其上架Prompt，纯图库卡片不依赖旧六档Prompt。图片仅在共享输入中携带一份，逐项显式覆盖强度/色调与卡片身份，旧档用null清除共享卡片，避免串用模板。

新增模板只读取既有光影库卡片正文，不发送卡片原图、不调用精模完整Prompt或Agent，仍为单张效果图和一次生成。实际正文为“用户原文 → 美化保护合同 → 卡片词”，不拼原自然调正文；Flux触发词随后追加且重复编译不前插。原空间结构、门窗、机位、家具布置及材质本色/纹理保留，照明按既有开口和灯具适配。见[工作台Prompt顺序](workbench-prompt-order.md)。

Flux的“低强度自然调”是新增模板的执行工作流：沿用1920长边等比推理、右下16像素补边/裁剪、2步、LoRA 0.45与ab通道匹配1，亮度/对比及色温节点保持旁路，输出档位继续复用现有合同。旧六档的正文、节点参数与后处理保持各自映射；OneAPI使用相应正文，不消费Flux LoRA阶段。

浏览器只提交 `effectBeautificationLighting={presetId,version,sha256}`。选原六档时该字段为null/省略；选择新增模板时服务端将 `effectBeautification` 固定为 `low/natural`，不受旧草稿残留值影响。卡片须在入队和执行时通过版本/SHA与真实正文校验，更新或下架阻断执行。其他功能拒绝携带该字段。实际Prompt、卡片身份及执行参数进入既有归档；Beta快照保留相同身份。

运行目录须声明 `generationFeatureCapabilities.effectBeautification.promptLighting=true`。旧进程不能接收新增模板，界面应提示更新工作台；六种原氛围仍兼容旧请求。共享库不可用时保留原六档，原六档Prompt不可用不影响有效新增模板。
