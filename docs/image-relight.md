# AI编辑 → 打光

用户在当前场景上选择不同光照模板，重新建立照明与阴影，按需编辑光源。运营正文由独立飞书「打光 Prompt」版本表管理，服务端不回退到代码或本地文件。原图作为空间、材质和物体布局的依据，原来的光照不作为五模板的保留目标。仅使用GPT Image 2.5 Sunburst（`gptImage25Sunburst`），功能ID为`imageRelight`，不进入Beta或Benchmark。

## 默认操作

1. 上传一张当前场景原图。
2. 选择光照模板，默认明亮漫射。
3. 点击START生成结果；需要自行处理原灯或布光则选“自定义”，直接选择原有灯光“保留／整体减弱／全部关闭”，按需新增光源或单灯精修。

| 光照模板 | 作用 |
| --- | --- |
| 明亮漫射 `naturalFill` | 中性高调、广泛漫射和弱投影，重建明亮空间 |
| 暖居夜景 `warmAmbient` | 压低日光并消除旧日影，以暖灯建立夜间分层照明 |
| 窗边斜阳 `windowDaylight` | 窗侧方向光与清楚的长投影，形成强主光关系 |
| 重点洗墙 `accentWash` | 压低环境光，以自上而下渐变洗光突出重点墙面 |
| 柔和摄影 `softStudio` | 中性大软侧光加弱补光，保留柔软塑形和阴影层次 |
| 自定义 `custom` | 原灯保留／整体减弱／全部关闭，可选新增光源或单灯精修 |

五模板按所选方案重建主光、补光、投影、反射与环境光，不锁定原图的亮度、白平衡、时段、灯具开关或旧主光方向。可以压低或关闭与新方案冲突的原灯贡献，清除旧投影后重算；保留灯具实体、设计风格、材质固有色、纹理、空间与机位。允许可信的画外/隐藏光源，不能因为原图看不到对应灯而退化为轻微补光；不新造窗洞或可见灯具。新增可见硬件仍须明确选择添加灯具。主灯照明/无主灯/自然采光三类旧方案只用于历史恢复，沿用原语义，不出现在新模板选择中。

### 自定义光源

选择“自定义”直接显示原有灯光三选及可选光源编辑，不再有“编辑光源”折叠入口。默认原灯“保留”；“整体减弱”与“全部关闭”无需逐灯标注，也不新增一次识别模型调用。整体减弱幅度10%–90%，默认50%。整体操作只作用于原图可识别人工灯源及相关间接光/反射，保留灯体和日光、本次新增补光；无可识别人工灯源时不强行压暗全图。仅保留原灯且无实际编辑不创建收费任务。选择五模板时只执行模板，不显示或提交自定义原灯处理和标记草稿；返回自定义恢复两者。旧模板加标注的任务恢复时，编辑面板直接可见，并说明该历史模板仍生效，保留原模板和编辑参数。

- 可选局部编辑分“新增光源”或“单灯精修”，两类标注可以放在同一任务。选中已有标注时，面板自动显示对应操作，不把新增灯切成减弱/关闭。
- 新增光源支持点、线、面及受光方向、2000–10000K色温、0.1–3相对亮度和软硬；较弱的新补光直接调低亮度。两种灯具模式保留为“只调整光照”或“添加灯具并点亮”，后者可填最多200字外观描述。
- 单灯精修先选“减弱”或“关闭”，再用点、线、面标出图中实际灯具或有限发光段，不在受光墙面上画压暗区域。这类标注没有方向、色温或新增灯具参数。减弱幅度为10%–90%，默认50%。
- 减弱/关闭只改变标注处可识别原光源的发光贡献及相关间接光/反射，保留灯体；找不到原光源则该动作保持原样，不虚构灯源或压暗任意受光面。“删除标注”仅移除编辑操作，不能代替关闭图中灯具。
- “保持不变”只兼容历史标注，不作为普通新建入口；恢复时可查看或移除，仍沿用既有生成约束和质量边界。

方向键移动标注，新增光源可用Shift＋方向键调整受光目标；支持撤销、清空、触屏取消和面内嵌套。画布是原图与编辑标记，不是实时光照效果预览。显示标注层按实际CSS尺寸×屏幕DPR绘制，窗口伸缩与换屏时重绘；不受原图像素大小限制，原图本身低清不会限制编号与轮廓清晰度。归一坐标与服务端送模guide仍按既有原图合同处理。内部ID稳定，可见编号与实际送模引导图一致。

### 默认参数与历史任务

界面移除“生成设置”块，不显示模型/输出/质量/幅度控件。新任务固定GPT、1K/medium和balanced适中，不提高默认成本。接口目录仍保留既有档位以兼容API与历史任务；恢复非默认历史参数时显示一行只读摘要，保留实际参数并明确提示，不静默切换或隐瞒。适中执行完整所选光影目标，自定义/三旧方案仍维持局部或原光协调语义。

## 请求与历史兼容

`GET /api/image-relight/config` 返回实时Key权限、唯一模型、输出/质量、模板/幅度、局部动作及`originalLightActions`整体原灯目录和`defaultOriginalLights={action:"keep"}`，以及仅元信息的`prompt`状态（code/version/sha256/source/tableUrl/versions）。`?forceRefresh=1`主动刷新飞书资产缓存，正文及bundle不公开。公开目录为五效果加自定义，`defaultTemplateKey=naturalFill`（明亮漫射）、`defaultBlendMode=balanced`。旧三方案在`legacyTemplates`返回。Prompt正文仅服务端，不进入浏览器。

新界面显式提交所选模板。服务端`normalizeRelightSettings`对省略`templateKey`的旧请求仍按`custom`处理，避免旧API或归档被静默套明亮漫射；这与新界面的默认选择分开。历史无`action`的标注仍按`brighten`增强读取；旧三方案恢复原key和原意，不自动映射到新模板。v4五效果沿用key但v5更改其照明语义与标签；历史归档的实际Prompt和版本不重写，新任务使用当前上架资产与执行版本，不把重跑称为精确复现旧结果。

`POST /api/generation-jobs`使用`featureMode=imageRelight`，固定单项。原图通过`sharedInput.referenceImages`仅传一次；模板允许零标注，自定义整体减弱/全部关闭本身就是实际动作，可零标注、仅单原图生成；保留原灯或无整体操作时，仍需至少一项新增光源或单灯精修，不能只有历史保护标注。普通模板任务不携带自定义草稿；历史模板加光源任务恢复后保持显式可见编辑与原始提交参数。

`originalLights`为整体原灯请求：`null`或`{action:"keep"}`／`{action:"darken",amount:0.1–0.9}`／`{action:"turnOff"}`。仅自定义可非null；模板及三旧方案只接受null，避免暗参重新锁定原光。省略/null归一为null，darken缺amount补0.5；keep/off不可携带amount，拒绝未知字段、动作和非法数值。新界面保留原灯明确提交keep，模板提交null；服务端、入队、执行与归档按值深冻结。

内部保留`lights`数组和动作合同以兼容历史，每项都有`id/type/points/action`：

| 内部动作 | 专属参数 | 语义 |
| --- | --- | --- |
| `brighten` | `target/mode/kelvin/intensity/softness/fixture` | 新增指定几何与方向的补光；只有明确addFixture可添加实体灯具 |
| `darken` | `amount`为0.1–0.9 | 减弱标注处可识别原光源及关联照明；无源时保持原样 |
| `turnOff` | 无 | 关闭既有灯源，保留灯具实体 |
| `preserve` | 无，历史兼容 | 保留所标对象的外观与照明意图，不是像素锁定 |

所有动作合计最多12条，每条最多64个轮廓点，坐标归一到0–1。增强要求有效受光目标和非退化方向；其他动作不携带方向或灯具/色温参数。内部冲突优先级仍以保护最高、关灯高于减弱；整体关闭不能被单灯减弱或补光重新点亮原灯，新请求的独立补光/新灯具照常执行。整体保留是原灯基线，不是接收面像素锁。规则不常驻产品主界面。

原图仅接受单帧PNG/JPEG/WebP，最多6MiB、单边4096px；服务端真实解码并归一EXIF，拒绝重复ID、无效数值、自交/零面积面和退化几何。原图比例须在1:3至3:1内，按模型目录选合法输出尺寸，实际返回必须为唯一且尺寸一致的原生PNG。

纯模板或仅整体原灯操作只提交干净原图；有局部标注再提交同尺寸编号动作引导图，只有新增光源带方向箭头。无mask、无区域裁切回贴，模型原生结果不调色或重编码。单次收费POST不自动重试，同工作台任务ID幂等；入队冻结模板、幅度和光源参数。目录不兼容、Key权限、飞书Schema或Prompt资产错误须在收费前阻断。入队前按请求的`relightPromptVersion/relightPromptSha256`解析上架资产，在服务端闭包冻结正文；排队期间修改/下架表记录不会替换已接任务的快照。旧客户端省略两字段时选当时最高上架版本，浏览器不允许提交私有bundle绕过读取。

## 飞书归档

沿用`imageRelight`独立scope和现有生成记录字段，不新增列。功能标记打光；参考图保存原件与可选实际送模引导PNG，结果图保存完整原生PNG，用户补充要求/实际提交正文分别归档，正文不返回任务快照。

生成参数保存整体`originalLights`、模板/幅度/来源、规范化光源、`lightingPlanSha256`摘要、版本/模型、原始/提交/请求和返回尺寸、EXIF、源/引导/结果SHA、费用及请求身份。归档前比较原请求、执行参数与实际回执，v3及以上须带动作和计划摘要并在写入前复核；v1/v2旧数据保持兼容；v10摘要加入canonical originalLights（含模板null），v1–v9保持旧字段集与已存Prompt，不注入keep或重拼历史。字段与附件token/字节数双回读完成后才报同步成功，失败保留结果并允许补归档，不重新收费生成。
